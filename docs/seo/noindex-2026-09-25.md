## Akar masalah dan implementasi

PublicContentQuality sebelumnya menjadi satu-satunya gerbang indeks publikasi/program/profil. Ambang kata merupakan kebijakan internal, bukan persyaratan Google. PublicContentIndexability sekarang mempertahankan jalur konten lengkap dan menambahkan bukti pendukung untuk konten ringkas: publikasi dengan ringkasan, tanggal, serta URL sumber HTTP(S) atau PDF publik yang benar-benar ada; program dengan deskripsi dan minimal dua bagian detail berbeda, atau dua learning points plus tanggal, atau tanggal/penyelenggara/lokasi; profil dengan bio dan kontribusi publik (atau minimal tiga kontribusi tanpa bio). Teks kosong, judul yang diulang sebagai deskripsi, dan frasa placeholder umum tetap ditolak. Ini heuristik lokal, bukan penilaian kualitas Google atau jaminan indeks. Draft, jadwal publikasi dan akses privat tetap dijaga oleh scope controller/sitemap yang sudah ada.

Ringkasan publikasi kini memakai excerpt jika description hanya HTML kosong. Keputusan baru dipakai bersama oleh controller, fallback template, sitemap dan ItemList. Aturan artikel Insight dan Multimedia tidak diubah. Normalisasi type=semua, tracking, view dan pagination sudah ada sebelum tugas ini; ditambah cakupan tes, tidak dibuat ulang.

Setelah review, deploy file PHP/Blade sesuai prosedur proyek. Jalankan `php artisan view:clear`; jika release memakai compiled views, buat ulang dengan `php artisan view:cache`. Tidak ada perubahan rute; ikuti prosedur cache konfigurasi/rute normal bila deployment membangunnya ulang. Build frontend hanya diperlukan jika release juga membawa perubahan frontend lain.

Periksa delapan detail di server: status, meta robots, X-Robots-Tag, canonical dan tampilan ringkasan. Pastikan URL sumber/PDF tersedia. Periksa sitemap bahwa halaman yang baru layak muncul, draft/placeholder tidak muncul, dan setiap URL tujuan merespons 200 tanpa redirect. Kemudian gunakan Inspeksi URL → Uji URL Aktif, minta pengindeksan hanya pada halaman yang layak, dan validasi perbaikan yang memang relevan.
